# Roadmap

Priorities follow maintainer usefulness and evidence quality. Dates are intentionally unset until there is usage evidence.

## Next: validate a real maintenance decision

Invite 5–10 willing maintainers to try one comparison they already need. Record their target, intended decision, time to a useful source pair, false positives, missed relevant files and what they changed or chose not to change. Obtain permission before publishing their examples or feedback. Ship fixes for repeated failures.

Success is a useful decision supported by both source passages. Stars, downloads and page views are secondary observations; they cannot substitute for this.

## Improve discovery

Add a larger, permissively licensed corpus with reproducible immutable captures, renamed-skill cases, explicit relevance judgments and published misses. Compare baseline name search against proposed improvements before adding dependencies.

## Earn confidence in semantic studies

Run the same input-only evaluation through different model families and independent human reviewers. Expand beyond authored short examples to long, contradictory and moved rules. Publish disagreements, abstentions, source coverage and effort. Decide whether semantic workflow complexity is justified by real tasks.

## Reduce friction

Consider an exportable local comparison report and user-supplied candidate lists after repeated requests. Improve error recovery based on issue reports. Keep offline/local use first-class and avoid a hosted model service unless a demonstrated need justifies it.

## Release discipline

Maintain tested wheel/sdist/Skill deliverables, Linux and Windows checks, fixture provenance, current commands and a readable migration guide. Treat older research as historical evidence, not as a permanent acceptance certificate.
